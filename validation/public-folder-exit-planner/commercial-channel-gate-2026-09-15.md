# Public Folder Exit Planner — commercial channel gate (2026-09-15)

## Decision
KEEP / ADVANCE. Competition is treated as demand evidence and a source of wedges, not an automatic kill signal.

## Product wedge
Automate the planning/modernisation layer before execution: ingest customer-supplied Public Folder inventory, recommend destination per workload, surface blockers/uncertainty, create migration waves, and render an executive/technical plan. Do not compete initially on moving bytes.

## Channel hypothesis
Primary buyer: Microsoft 365 MSP / migration consultancy. The planner is a pre-sales + scoping accelerator that can be white-labelled. Partner retains the larger migration implementation project.

## Fresh evidence
1. MSAdvance (Spain/global remote) explicitly sells Microsoft 365 consulting, assessments and migrations and reports 200+ tenant-to-tenant projects and 500+ organisations supported. This is direct evidence of an addressable Spanish-speaking partner profile.
2. FuturaSP (Spain) sells Microsoft 365 migration/support nationwide, another plausible smaller-MSP profile.
3. ITCM Solutions (Spain) sells Microsoft 365 tenant administration and migrations, another channel candidate.
4. ExchangeSavvy offers a dedicated Public Folder Connector to Shared Mailboxes, SharePoint, M365 Groups/Teams, file shares and PST. Strong evidence that customers pay for heterogeneous Public Folder exits.
5. BitTitan's current guides expose destination limitations and migration edge cases; e.g. Public Folders are generally large and more error-prone, and its PF routes do not cover all modern destinations. This leaves room for vendor-neutral planning.
6. Keepit warns that Public Folder backup/restore stops in October 2026 because Graph does not support Public Folders. This creates a near-term trigger beyond migration itself: continuity/backup dependencies.
7. Microsoft still documents Public Folders as supported, so the pitch must NOT falsely claim that Public Folders themselves are being retired. The urgency is EWS/third-party programmatic access and modernization risk, not product EOL.

## Balanced competition rule
Competition increases confidence when it proves spend, urgency, channel or buyer familiarity. Penalize only when it removes a defensible wedge after comparing price, speed, geography/language, segment, workflow, distribution, integrations and business model.

## Proposed offer tests (no paid spend)
A. White-label assessment for MSPs: free first assessment, then per-report or credits.
B. Fixed-price direct assessment: test willingness around EUR 490–990 before raising price.
C. Assisted assessment: software output + expert review, benchmarked below manual planning engagements.

Do not lock pricing until buyer conversations/signals exist.

## Partner qualification score
Score 0–2 each (10 max):
- Explicit Exchange/M365 migration service
- Assessment/consulting already sold
- Serves SMB/midmarket where automation improves margins
- Spanish/European distribution advantage
- Evidence of recurring migration volume

Advance outreach validation when >=20 plausible partners are identified, including >=8 scoring 7/10 or higher.

## Current named seed set
- MSAdvance — strong: assessment + migrations + substantial published volume; Spain + international.
- FuturaSP — medium: Spain-wide M365 migration/support; likely SMB channel.
- ITCM Solutions — medium: M365 administration/migrations; Spanish market.
- ExchangeSavvy — competitor/benchmark, not initial channel.
- BitTitan — competitor/tool ecosystem benchmark; its limitations help define vendor-neutral wedge.

## Critical falsifiers
- MSPs say planning is already negligible/free and produces no sales friction.
- Inventories lack enough semantic/business evidence to make useful destination recommendations without lengthy stakeholder interviews.
- Liability/trust makes automated recommendations unusable even as draft scoping.
- Acquisition cost/time per MSP exceeds expected gross profit from assessments or downstream partner usage.

## Next gate
Build a 20–50 MSP prospect evidence set and test whether the report can function as a sales/scoping artifact. Do not create a public Rockrai site until this distribution gate is materially supported, unless a public demo becomes necessary to validate buyers.

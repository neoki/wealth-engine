# Candidates
Candidates are the small set of signals worth additional evidence. Maximum active candidates is governed by `governance.json`/`STATE.json` (currently 5).

Each candidate must expose thesis, buyer, pain/job, evidence, competition interpretation, monetization, smallest falsifiable test, success/kill gate and next uncertainty.

After at most 3 consecutive autonomous cycles, rotate unless genuinely decision-changing evidence justifies another. When execution becomes dominant, PROMOTE and create a child bootstrap under `projects/`.
